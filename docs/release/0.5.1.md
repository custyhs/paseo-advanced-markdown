# Advanced Markdown 0.5.1

Fixes the way back from **Show original**. In 0.5.0 the only control that
returned a turn to plugin rendering was a composer pill labelled "Original view
· 1 turn". Paseo cut that label off, and it named a state instead of an action,
so the turn looked stuck as TeX source. Both app and daemon require **Paseo
>=0.13.0**, without an upper version limit.

## Changes

- The pill above the composer now reads **Show rendered**, mirroring the
  footer's Show original, and is short enough for Paseo to show whole. Pressing
  it returns that agent's turns to plugin rendering, as before.
- A turn in the original view returns to plugin rendering on its own when the
  agent starts its next turn. While an agent has turns in the original view,
  the plugin subscribes to that agent's live timeline through Paseo's API and
  restores them on the daemon's turn-start event. If the subscription cannot be
  established, the pill and a reload still restore.
- Settings, saved data, and every other 0.5.0 behavior are unchanged.

## Compatibility

- Same requirements and limits as 0.5.0; see the
  [0.5.0 release notes](0.5.0.md) and the
  [README](../../README.md#reply-actions-and-compatibility).
- A panel without a composer, such as an archived agent, shows no pill. A
  reload restores there.

## Validation

- Build, typecheck, lint, and formatting checks passed, plus the official Paseo
  0.13.0 compiler smoke with v0.8.0 projection fixtures and the Hermes bundle
  smoke (`npm run smoke:hermes`, default flags and `-Xes6-class`).
- All 34 test files passed, run one file at a time. `tests/reply-runtime.test.ts`
  gained eight tests for the pill label, the turn-start restore, the watch's
  lifetime, and a failing subscription.
- The pinned-host pipeline check (`npm run host-source && npm run qa:reply-actions`)
  passed 13 cases on each of official Paseo v0.15.3, v0.16.0, and the head of
  getpaseo/paseo#9253.
- The generated npm package passed `smoke:package` against official Paseo
  0.13.0, 0.14.0, and 0.16.2 runtimes, and `npm audit` reported no production
  vulnerabilities.
- Real-client checks ran on an isolated official Paseo 0.16.1 daemon with
  Better Paseo enabled: the pill shows its whole label and restores when
  pressed at 1100 and 390 pixels, and sending a prompt restored a turn in the
  original view at 1100 pixels with Claude Code. Not checked: the next-turn
  restore at 390 pixels or with Codex, Electron, iOS, and Android. See the
  [QA record](../qa/fork-safe-replies.md#051-follow-up-the-way-back).

## Update

For an existing npm installation:

```bash
paseo plugin update advanced-markdown --version 0.5.1
```

For an existing Git installation:

```bash
paseo plugin update advanced-markdown --ref v0.5.1
```

Paseo 0.11–0.12 users should stay on v0.3.2; Paseo 0.8–0.10 users should stay
on v0.3.0.
