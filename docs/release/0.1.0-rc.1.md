# Release review: advanced-markdown 0.1.0-rc.1 (final: v0.1.0, patched by v0.1.1)

`v0.1.1` adds Linux host support details only: the browser-launch failure now
reports its cause with a hint, `PASEO_ADVANCED_MARKDOWN_NO_SANDBOX=1` opts out of
Chrome's sandbox on hosts that restrict unprivileged user namespaces (Ubuntu
24.04 default), and CI validates the Linux runtime on ubuntu-24.04 runners.
Math, Mermaid rendering, and client code are unchanged from `v0.1.0`.

Final tag `v0.1.0` points at the commit that adds this paragraph. Its runtime
code (`client/`, `server/`, `shared/`, `worker/`, build and preparation
scripts, manifest) is identical to `v0.1.0-rc.1`; the commits in between add
documentation, QA helpers, and samples only.

Candidate: tag `v0.1.0-rc.1` = commit `59d39a8375bd3fd773a8981254c3d33a15ff8e06`.
Commits after the tag change only `docs/`, `scripts/qa/`, and the QA capture
helper; no runtime code (`client/`, `server/`, `shared/`, `scripts/build.mjs`,
`scripts/prepare-browser.mjs`, `worker/`, manifest) changed after the tag.

## Installation, update, and rollback (host B, official daemon 0.8.0)

| Step | Result |
| --- | --- |
| `plugin add file:///tmp/pam.git --ref v0.1.0-rc.1` | staging build ran `npm ci`, `npm run build`, `npm run prepare-browser`; activation moved the checkout to `plugins/advanced-markdown/<commit>-<uuid>/checkout`; status RPC reported the Mermaid runtime ready from the moved checkout; a diagram rendered; 12 s with warm npm and browser caches |
| `plugin add … --ref main` then push a commit that breaks `npm run build` and `plugin update` | update failed with the build output in the error; `plugin ls` kept the previous commit and `status: running`; the status RPC still answered from the old version |
| push a fix with a version bump, `plugin update` | 13 s; status RPC reported the new version; the previous version directory was removed and `.staging` was empty |
| `plugin remove` then `plugin add --ref v0.1.0-rc.1` | back to 0.1.0; status ready |

The daemon-side cache (`~/.cache/paseo-advanced-markdown`) is reused across
installs and updates; it is not removed by `plugin remove`.

## Known limitations

- Images, not text: no MathML, no text selection across formulas, no SVG
  node interaction. Copy source is the escape hatch.
- Bare `$$` display math with blank lines is split by Paseo while streaming;
  use a `math` fence.
- Mermaid runtime is 670 MiB on disk (462 MiB CLI runtime + 208 MiB browser).
- Mermaid renders serially at about 0.35 s each after a warm start; a
  400-node diagram takes ~6 s (two passes).
- Settings changes apply to rows projected afterwards; rows already on screen
  keep their state until reload or reopen.
- Only one timeline plugin can own a row; do not enable another math/Markdown
  replacement plugin at the same time.

## Cutover notes for the production machine

Not performed. When chosen: upgrade the production app and daemon to official
0.8.0, enable plugins, `paseo plugin add custyhs/paseo-advanced-markdown --ref v0.1.0`
(after pushing and tagging), and disable any other timeline plugin that
replaces assistant rows. The fork's built-in math rendering does not have to
be removed first; on an official build it is simply absent.
